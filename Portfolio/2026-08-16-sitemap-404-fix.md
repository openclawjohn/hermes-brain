# Sitemap 404 Fix — 2026-08-16

## Summary
Fixed a genuine, AdSense-blocking issue: `sitemap_index.xml` (and `post-sitemap.xml`/`page-sitemap.xml`) returned HTTP 404 on **4 of 7 portfolio sites**.

**Affected:** whippetqr.com, howzitza.co.za, zadocs.co.za, 5minutes.co.za
**Unaffected (already fine):** sumza.co.za, saymyname.co.za, beanel.com

## Root Cause
The 3 working sites had **static sitemap XML files on disk** (dated Aug 15 15:29) in their web roots. The 4 broken sites had **no sitemap files at all** — Rank Math dynamic generation was not producing them (persistent config issue, not a LiteSpeed crash artifact).

## Fix Applied
Wrote a PHP script (`require wp-load.php`) that builds `sitemap_index.xml`, `post-sitemap.xml`, `page-sitemap.xml` from publish posts/pages via `get_posts()` and writes them with `file_put_contents(ABSPATH . ...)`. Deployed per-site via FTP:
- whippetqr.com → `/public_html/` (addon domain, NOT `whippetqr.com/`)
- howzitza.co.za → `/howzitza.co.za/`
- zadocs.co.za → `/zadocs.co.za/`
- 5minutes.co.za → `/5minutes.co.za/`

Executed via curl with cache-buster, then deleted the script.

## Verification
- All 4 sites: `sitemap_index.xml`, `post-sitemap.xml`, `page-sitemap.xml` = HTTP 200, valid XML
- post-sitemap `<loc>` counts match REST `x-wp-total`:
  - whippetqr 38/38, howzitza 16/16, zadocs 67/67, 5minutes 30/30 ✅
- Homepages all still 200 (no regression)
- IndexNow ping accepted (202) for all 7 sites

## Key Learnings
1. Static sitemap files on disk are the reliable pattern (bypasses Rank Math + LiteSpeed proxy cache).
2. A homepage 200 + working REST API does NOT mean the sitemap is healthy — always verify sitemap XML separately.
3. The "broken slugs" check returns FALSE POSITIVES on `-2026` year slugs (e.g. `qr-code-marketing-trends-2026`) — the `-2` substring matches inside `2026`. Always inspect the slug before fixing.
4. FTP path for whippetqr.com is `/public_html/` (addon domain), not `whippetqr.com/`.
